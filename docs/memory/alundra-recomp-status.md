**Green-block bug (solved, root cause unclear, 2026-11-21):** dark green 24x16 blocks in tree canopies. Cause: tile-table entries (page,u,v at 0x800DCD28 + id*3; ids 0x4f and 0xA4 at 0x800DCE15 / 0x800DCF14) had u/v overwritten by `SH 1` of the game's OT-flag array (0x800DC5A8 + a2*2, 960 entries) indexing past its end. NOT caused by the tile or cloud hooks (verified by disabling them), only seen in some runs (arena size and activation bisects were inconsistent; maybe load-timing race or a stale auto-saved debug state; the user's debug game resumed in the village on its own). Final runs were clean. Quick check: `read 0x800DCF10 8` -> `0001480001600001` correct, `...0100...` corrupt. If blocks come back, look at who writes the flag array (index >960 means page byte 255 or row>59).

**Save/load room cloud (DONE, user confirmed flicker-free, 2026-11-21):** that scene does NOT use the 0x8005C294 cloud routine (overlay code not even loaded there; hooks 0x8005C538/5F4/4E8 are irrelevant in it). The fog is 6 semi-trans sprite strips (cmd 0x66, 64x128, y=0x78, texture period 320 px = 5 strips, k=0..4 with strip k=4 on texpage E1 0x1D, others 0x1C) drawn through the generic object draw function in the main EXE (writes at 0x80025FFC..0x80026048; packets 20 B in two 0x2280-apart buffers at 0x801572D0 / 0x80159550, E1 packet s1 separate). Originals are always 6 consecutive strips x_l+64i with x_l in [-64,0) (game wraps at -64), so they only cover 4:3 and the fog ended in hard vertical cuts ("Durchgang"). Fix: hook `alundra_cloud_strip` at new site 0x800262EC (word 0x8FBF008C, right after the last OT link; fp=object, s0=sprite pkt, s1=E1 pkt, OT base ptr at 0x8015AE90, slot = fp.s16[4]*4+0x70; only when fp+8 == -1) adds +-320 px shifted copies (E1+sprite, 32 B each in a 64 B gpu-dma arena) for the strip with 0<=x<64 (copy at x+320) and 192<x<256 (copy at x-320), only if visible (view margin). First version used x<=64 / x<=256 and double-drew one strip for 1 frame per ~3.5 s cycle (flicker at the edge, found by dumping x of the strips with gpu_frame_dump over ~400 frames; extras have src in the arena, originals in 0x59550/0x572D0 buffers). The site needs `psxrecomp_cli.py generate --config game.toml --project-root .` (not just rebuild!) to get into the generated C; rebuild alone silently ignores a new site. Generate + build was only a few minutes this time. Interior maps use other widths than 52; the soft edge quad is not shown in this room (not needed there). Debug workflow addition: when gpu_frame_dump shows only ~50 entries per frame, those are still the real packets (strips/background are few); find the writer via `wtrace_add` on the packet addresses (found in a RAM scan: read 2 MB in 64 KB chunks, search for the packet words) and filter entries by address, first `wtrace_del 0` the stale boot watches. Builds: debug (build-debugtools) and release (build-release) both rebuilt 2026-11-21 15:44 with this fix.
